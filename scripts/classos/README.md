## 為什麼不把 f24 與 f29 併成一支

**刻意分開：一支只算、一支只寫。** f24 每週五自動跑、任何人都可以看；f29 會真的動錢，
必須手動選 task＋mode=execute 兩道才跑得起來。合併會讓「試算」與「入帳」共用一個入口，
等於把最後那道人工閘門拿掉——這是把關三分類的底線，不是重複程式碼。

## 共用的三條寫入規矩（新腳本照抄）

1. **預設 dry-run**：`isExecute()` 為假就只印不寫；Actions 的 mode 預設 dry-run。
2. **防重複鍵要含「對象」**：一筆來源可掛多位學生，鍵只用來源 id 會讓第二位以後被靜默漏掉（U41）。
3. **execute 後一定回讀驗收**：比對筆數與防重複鍵，不要相信自己的計數器——
   2026-09-12 f29 第一版把 `api()` 的回傳當成頁物件，53 筆明明寫進去了卻全報失敗，
   是回讀那一關把真相說出來的。
