# 🏦 班級銀行制度設計（崑山幣）

> Phase 2｜金融教育・模擬社會工作生活。適用對象：國小中年級。
> 設計原則：**公式寫死、整數運算、老師可一句話覆寫**（模型無關性）。
> 2026-07-07 初版。所有金額數字老師都可調整，調整後同步更新本文件與 /class-bank skill。

## 一、貨幣

- 名稱：**崑山幣**（單位「幣」，記帳一律整數）。
- 只存在於 Notion「🏦 班級銀行帳本」，無實體代幣（避免遺失與糾紛）。
- **餘額不可為負**：消費前先檢查餘額，不足則不能購買（不開放借貸）。
- 學生之間**不開放轉帳**（避免勒索、代寫作業等變相交易）。

## 二、收入：班級職務＝工作（週薪制）

每位學生至少擔任一項職務，每週五發薪。三級薪水制：

| 職級 | 職務範例 | 週薪 |
|---|---|---|
| 領導職 | 班長、副班長 | 30 幣 |
| 股長職 | 風紀、衛生、學藝、體育股長、各科小老師 | 25 幣 |
| 專員職 | 電燈、門窗、圖書、澆花、黑板、排長、設備專員 | 20 幣 |

- 值日生輪值屬全班義務，不另計薪。
- 該週明顯失職（老師認定，紀錄庫有紀錄佐證）：該週薪水減半（無條件捨去）。
- 職務異動時老師口頭告知 /class-bank 更新職務表即可。

## 三、獎懲金：紀錄庫自動換算

/class-log 記錄時自動計算「金幣影響」欄，公式**寫死**：

```
金幣影響 = 正負向(＋1/－1) × 程度(1–3) × 5
亮點類加倍：金幣影響 = 程度 × 10
中性紀錄：0（不入帳）
```

- 例：「數學小考粗心 −1」→ −5 幣；「主動幫同學搬作業 ＋2」→ +10 幣；「亮點・程度2」→ +20 幣。
- **定期評量進步獎（成績庫連動）**：成績庫「進步獎」勾選者，每次評量 +20 幣
  （老師說「發進步獎」由 /class-bank 批次入帳，防重複）。
- **固定獎勵表（2026-07-20 新增，金額不走程度公式，記錄時直接填金幣影響）**：

  | 項目 | 金額 | 說明 |
  |---|---|---|
  | 參加比賽獲獎・校內 | +20 幣 | 含入選、佳作以上名次 |
  | 參加比賽獲獎・市賽（縣市級） | +40 幣 | 代表學校參加之縣市層級競賽獲獎 |
  | 參加比賽獲獎・全國賽 | +80 幣 | 全國層級競賽獲獎 |
  | 學校活動・布可星球（閱讀書數） | 每累積滿 10 本 +20 幣 | 以平台認證通過本數計，10 本為一級距批次入帳；老師回報累積本數時，與上次已入帳級距比對補發差額，防重複 |

  - 同一比賽獲多個獎項取最高一項；金額老師可於記錄當下口頭覆寫。
  - 記錄方式：由 /class-log 以「亮點」類別入帳（事由寫明比賽名稱／布可累積本數），金幣影響直接填上表金額。
- 老師可在記錄當下口頭覆寫（「這筆算 +15」），以老師覆寫為準。
- 懲金扣到餘額歸零為止，不會扣成負數（差額不追討，教育重點是行為回饋不是債務）。
- 入帳時機：/class-bank 執行「結算獎懲」時批次入帳（建議每週五與發薪一起），
  已入帳的紀錄在帳本留有紀錄庫 relation，**不會重複入帳**。

## 四、打掃薪水與 XP（週結）　※2026-08-14 改版，取代原本的儲蓄利息

### 4-1　~~儲蓄利息~~ **已停用**

```
（舊制）利息 = floor(結算時餘額 × 5%)，單週上限 20 幣
```

**2026-08-14 起不再計息**。停用理由：利息是「餘額的函數」，越有錢長越快，
和學生做了什麼完全無關；要讓孩子看見的是「行為會累積」，不是「存款會自己長大」。
舊的利息帳一律保留，存摺照樣顯示得出來；Notion 的「利息」類型選項也保留，只是不再新增。

### 4-2　工作薪水：打掃／午餐／班級常規（新增）

```
打掃薪水     = 本週打掃次數     × 2 幣
午餐工作薪水 = 本週午餐工作次數 × 2 幣
班級常規獎勵 = 達成天數 × 1 幣 ＋（五天全達成再 +3 全勤獎）　週上限 8
```

**一律依「次數」不依「天數」**：一天可能支援 2–3 次打掃；午餐長／打飯班天天做、
搬餐桶每週輪一組——用「一份工作」或「幾天」算都會失真，**做幾次就算幾次才公平**。

**次數怎麼來：基準 ＋ 例外**（老師平常什麼都不用做）

```
本週次數 = 工作分配表的固定基準 ＋ 支援次數 − 缺席次數
```

| 項目 | 固定基準 |
|---|---|
| 打掃 | 被指派的工作份數 × 5 天（多數人 1 份＝5 次；掛 support 的＝10 次） |
| 午餐 | 午餐長／打飯班固定 5 次；輪值池**只有輪到的那一週**算 5 次，沒輪到 0 次 |

只有臨時支援與請假缺席要記一筆，週結自動加減。

**班級常規獎勵：保底 ＋ 全勤**

- **每天達成 +1**（保底）：週三破功的孩子，週四、週五還有得拿，
  不會因為「這週已經沒了」就整週放棄——這正是全有全無制最大的副作用。
- **五天全達成再 +3**（全勤獎）：保留「全部做到才有」的份量，一週最高 8 點。
- 判定採**例外管理**：預設當週 5 天都達成，老師記到該生常規未達成才那天不給。
  **這是「不給獎」不是「扣錢」**，與「常規沒做到只重做、不扣幣」的鐵則不衝突。

- 每週五與發薪一起入帳，類型都是「薪水」，事由分別寫「第N週打掃薪水／午餐工作薪水／班級常規獎勵（X 天或次 × N 幣）」。
- **沒做好不扣薪水**——那是班規 ③「打掃要認真」的事（−5，量尺 −1），
  同一件事不扣兩次。薪水對應的是「有沒有這份責任」，扣點對應的是「這次做得如何」。
- 教育目標：每天做好的本分要看得見，而不是只有出錯時才被記一筆。
  它同時是 XP 最穩定的來源，讓願意扛責任的孩子追得到職務公會的門檻。

### 4-3　雙貨幣：崑山幣與 XP

| | 崑山幣 | XP（累積經驗值） |
|---|---|---|
| 是什麼 | 流動資產，用來消費 | 年輪，記錄做過多少好事、扛過多少責任 |
| 怎麼增加 | 薪水、獎勵金 | **只有薪水與獎勵金**（正數） |
| 會不會減少 | 會（消費、懲罰金） | **不會**——花錢、被扣點都不影響 |
| 用來做什麼 | 買商店的特權 | 解鎖第三、四層的職務與提案權 |

#### XP 分兩條軌（2026-08-14 擴充：在校的每一種行為都有數值回饋）

| 來源 | 帳本類型 | 金額 | 算哪一條 |
|---|---|---|---|
| 幹部週薪 | 薪水 | 20／25／30（依職級） | **責任 XP** |
| 打掃薪水 | 薪水 | **次數** × 2 | **責任 XP** |
| 午餐工作薪水 | 薪水 | **次數** × 2 | **責任 XP** |
| 班級常規獎勵 | 薪水 | 達成天數 × 1 ＋ 全勤 3（週上限 8） | **責任 XP** |
| 正向行為 | 獎勵金 | 品格量尺級數 × 5（+5／+10／+15） | **貢獻 XP** |
| 亮點（比賽、布可星球） | 獎勵金 | 程度 × 10 | **貢獻 XP** |
| 定期評量進步獎 | 獎勵金 | +20 | **貢獻 XP** |
| 消費／懲罰金 | 消費／懲罰金 | 負數 | 不影響（XP 只增不減） |
| 手動調整 | 調整 | 任意 | **不計入**（補正用，計入等於可人工灌水） |
| ~~利息~~ | ~~利息~~ | 已停用 | 不計入 |

**為什麼要拆兩條**：薪水類幾乎是「有來上學、有把本分做完」就會穩定累積。
全部混成一個數字，XP 就變成出席時數，職務公會的門檻也就變成「熬到就有」。
拆開之後，職務要求「總 XP 到門檻**且**貢獻 XP 也到門檻」——光出席拿不到。
學習報告上兩條軌畫成一條雙色長條，孩子看得出自己是「本分做得穩」還是「額外多做了」。

- XP 由班網同步時自動加總（`sync-notion.mjs` 的 `bankFinanceBySeat`），不必人工維護；
  記帳時**只要類型記對，XP 就是對的**。
- XP 與稱號**只出現在該生自己的加密學習報告裡，不做全班排行**——
  XP 只增不減，公開排序等於一張永遠追不上的排行榜，與「成績不排名」是同一個道理。
- 稱號階梯（以總 XP 計，依一學期 20 週、責任 XP 約 45–55／週估算）：
  🌱 新芽（0）→ ⭐ 小星星（300）→ 🌟 閃耀之星（700）→ 💫 超新星（1200）→ 🏆 星際隊長（1800）。

## 五、支出：班級商店

Notion「🏪 班級商店」管理品項。**2026-09-02 全面盤點後現行上架 30 項**（①4／②16／③6／④2／⑤2）。

| 分類（功能欄） | 意義 | 對應層級 |
|---|---|---|
| 🎟️ 特權 | 核可後**發券**（有使用次數，要另外核銷）| ①②③④ |
| 🎁 小物 | 核可後**直接給**，不發券 | ⑤ |

**「分類」是給程式判斷的，「層級」是給孩子看的**——Apps Script 只認 `分類==="特權"` 來決定要不要發券
（`apps-script-proxy-v2.gs` 的 `isPrivilege`），所以⑤層實物一律歸「小物」，語意正確且不必改代理程式。

### 商店四層架構（2026-08-14，獎勵制度 V3）

櫥窗改依「層級」欄分組，把增強物從「只能用崑山幣買」往「靠累積的責任解鎖」推：

| 層級 | 是什麼 | 現況 |
|---|---|---|
| ① 社會性・免費即時 | 做到了就有，不花幣 | **4 項**（2026-09-02 上架）：🌟 今日之星／💌 好消息聯絡簿／🏅 榮譽牆展示／🤝 信任任務。價 0，說明欄一律以「【老師頒予・不可兌換】」開頭 |
| ② 活動特權・消費型 | 用崑山幣兌換 | **15 項上架**（30～150 幣）＋ 3 項備而不上（🧸 吉祥物保管 35／📸 攝影師 40／🍽️ 與老師同桌午餐 50），供月度輪換 |
| ③ 職務公會・解鎖型 | 要先達到 XP 門檻，換到的是責任與薪水 | **6 項**：班級小主人券（總 300／貢獻 60）、幹部見習券 70（400／80）、一日晨間主持人券 80（450／100）、訂正小幫手券 90（500／120・需受訓）、一日小老師券 100（600／150）、一日班長體驗券 120（900／250） |
| ④ 創造沙盒・系統演化 | 提案修改常規、自行設計商品 | **2026-09-02 開放**：🧪 創造提案權 0 幣（總 XP 1200／貢獻 350）＋ 🏷️ 命名權 0 幣（**達成條件後自己來換**，非老師頒予）。流程見下方 §五之三 |
| ⑤ 實物兌換・最後手段 | 拿得到手的東西 | **2026-09-02 新增**（原「實物」一直沒有層級）：✏️ 文具兌換券 30／🍎 食物兌換券 30 兩張。詳見 §五之四 |

**①層與命名權為什麼不能出「我要兌換」鈕**：價格 0 會讓前台「買得起就出鈕」的判斷對全班成立，
變成人人可點，那就不是「做到了才有」，整層的教育意義會反過來。
`bank.js` 因此加了 `awardOnly()`——說明欄以「【老師頒予」開頭的品項改顯示「🎖️ 老師頒予」，
並隱藏庫存與售完樣式（2026-09-02）。**新增這類品項時說明欄一定要帶這個前綴，否則會冒出兌換鈕。**
目前只有①層四項適用；④層的 🏷️ 命名權**刻意不加前綴**——它是達成條件後自己來換的（見 §五之三）。

- 「分類」欄（特權／小物）**不動**：它是功能性的，兌換核銷與 Apps Script 都靠它判斷。
  四層架構走獨立的「層級」欄，沒填一律當第二層。
- 職務公會**維持原價**，XP 門檻是額外資格——不是有錢就能買，但也不是免費。
  要不要改成 0 元純解鎖，等跑一學期看實際狀況再調。

- **②層刻意留 3 項備而不上**：上架 15 張已接近選擇困難的上限，再加會品項通膨。
  備用品項每月輪換 1–2 張，櫥窗有新鮮感又不膨脹。

- 定價原則：最便宜品項 ≈ 一週基本薪水的 2/3（存一週就買得起，建立正向循環）；
  最貴特權 ≈ 五週薪水（練習延宕滿足）。
- 購買流程：學生課後向老師登記 → 老師一句話記帳（「座號5 買自由閱讀券」）→
  /class-bank 檢查餘額、扣款、商店庫存 −1。
- 庫存 0 自動下架（前台顯示售完）。

### 五之三、創造沙盒的四步流程（2026-09-02 開放）

原本擋住④層的理由是「需要學生端寫入權限」。改成下面的流程後，**所有寫入仍然只有老師做**，理由消失：

| 步驟 | 誰做 | 怎麼做 |
|---|---|---|
| 1. 申請 | 學生 | 班網商店按「🧪 創造提案權」送出（0 幣，但 XP 未達 1200／350 不會出現按鈕）|
| 2. 核准 | 老師 | 教師專區核可，學生繳交書面計畫 |
| 3. 執行與回報 | 學生 | 依計畫執行，回報成果 |
| 4. 裁決與兌換 | 老師裁決、**學生自己換** | 你一句話記錄裁決；通過後**學生到商店自己按「🏷️ 命名權」兌換**（0 幣，解鎖條件欄寫明要先完成提案），你核可 |

- **XP 分兩段給**：提案通過 +10 貢獻 XP，成果通過再 +20。失敗但認真執行的仍給第一段——鼓勵的是提案這個行為本身。
- **命名權是「換來的」不是「給的」**（2026-09-02 老師定調）：頒予會讓它變成老師的恩賜，
  自己去換才是「我達成了條件、我來領我應得的」。所以它留在商店裡出兌換鈕，
  只是解鎖條件寫明要先完成提案——**把關發生在核可那一刻，不是把按鈕藏起來**。
- **系統只判流程，不判品質**：成果好不好是教學專業判斷，交給模型自動判會出事（通用鐵則 1：Check 保留人為節點）。
  系統負責的是三個階段有沒有走完、XP 有沒有給、命名權有沒有發。
- **提案護欄**（寫進提案單）：不得牴觸校規、不得涉及金錢或實物採購、不得增加同學負擔、不得購買豁免代價。老師保留否決權。
- ⚠️ **命名權不掛姓名座號**：班網公開頁不得出現學生全名與座號（通用鐵則 6），
  命名只能是學生自取的名稱（例如「閃電打掃法」），不能標「◯◯號提案」。
- **狀態這輪先走紙本＋一句話記錄，不新增資料庫**：一學期提案量大概個位數，
  新流程按通用鐵則 1 要先手動跑 1–2 輪、Check 標準穩定，才決定要不要開「🧪 創造提案」DB。

### 五之四、第五層：實物兌換（2026-09-02 新增）

實物是 CW-FIT 四類增強物的**最末位**，2026-07-26 曾整層下架。但「不上架」與「沒有這一層」是兩回事——
下架的實物品項留在庫裡卻沒有層級，盤點時才發現它們一直是分類上的孤兒。現在補一層讓它有位置。

**櫥窗刻意把它排在最後**（`bank.js` 的 `TIERS` 陣列末位，提示語「拿得到手的東西，但排在最後——前面四種都是花錢買不到的」）。
排最後不是嫌棄，是把「社會性 ＞ 活動／特權 ＞ 實物」這條原則做成孩子滑到底才看見的順序。

**選品鐵則：老師身邊即可取得，不特意花錢採購。**

**只放兩張券，不逐項列品**（2026-09-02 定案）：

| 品項 | 價格 | 換到什麼 |
|---|---|---|
| ✏️ 文具兌換券 | 30 | 老師手邊現有的文具**任選一件**（鉛筆、橡皮擦、便條紙、獎勵貼紙…）|
| 🍎 食物兌換券 | 30 | 營養午餐發剩的水果或乳品、或老師手邊的零食**任選一份** |

- **為什麼是券不是品項**：逐項上架（鉛筆一枝、橡皮擦一個、水果一份…）櫥窗會迅速膨脹，
  而且每一項的庫存都要老師回頭維護。**改成兩張「任選一件」的券，品項數固定為 2，庫存也不必逐項追**——
  真正的把關發生在核可那一刻（今天有什麼、還剩不剩）。
- **定價刻意不低於②層**（30，與活動券同區間）。實物若定成全店最便宜，會變成孩子的首選，
  反過來排擠社會性與活動增強物——**價格是制度的表態**。
- **食物券沒貨就退回申請、不扣崑山幣**（說明欄已寫明），老師不必天天回頭改庫存。
- 原本逐項的實物列（含五項採購型小物：可愛貼紙、造型橡皮擦、造型鉛筆、香香鉛筆、小文具福袋）
  已標【待刪】並登記待刪清單，**由老師手動刪除**。

### 五之五、班級共同目標（集資，2026-08-14 建置・**預設關閉**）

原始構想是商店裡一件「【集資】期末夢幻餐點 5000 幣」的品項。**沒有照做，理由如下**：
系統的帳本每一筆都必須掛在一位學生身上，沒有「班級共同帳戶」這種東西；
硬做一個共同帳戶等於多一份要對帳、要防呆、要寫進手冊的資料源，換來的只是一條進度條。

改用**既有帳本表達**，不新增資料庫、不改兌換流程：

| 面向 | 做法 |
|---|---|
| 捐款 | 帳本一筆普通「消費」：`類型=消費、金額=−N、事由="集資・<目標名>"` |
| 辨識 | 同步腳本抓 `類型=消費` 且事由符合 `/^\s*集資/` 的所有帳列，加總絕對值 |
| 開關與參數 | Notion「⚙️ 網站設定」四列：班級共同目標（開／否）、名稱、金額、說明 |
| 前台 | `data/class-goal.json` → 「🏦 小小銀行」進度條；關閉時整塊不渲染 |
| 隱私 | 公開頁**只出總額與捐款人數**，不出姓名、座號、也不出誰捐多少 |

三個設計決定：

1. **捐款扣崑山幣但不影響 XP**。XP 只增不減，消費本來就不進 XP——這裡順勢成為制度語言：
   「付出不會讓你變窮，只會讓紀錄更好看。」若捐款會扣 XP，等於懲罰慷慨。
2. **不列個人捐款金額**。公開頁列出「誰捐了多少」，實質是把各家的餘裕程度攤在網路上；
   孩子自己的存摺看得到自己捐了多少，這樣就夠了。
3. **預設關閉、老師自己開**。5000 幣約等於全班 3–4 週的總薪水，開太早會排擠個人存錢目標；
   建議跑滿一輪週結、看過實際水位再開。

## 六、每週例行流程（老師視角）

每週五放學前一句話：「**class-bank 週結**」→ 系統依序：
1. 發薪：依職務表為全班入帳週薪。
2. 結算獎懲：撈本週紀錄庫有金幣影響且未入帳的紀錄，批次入帳。
3. 工作薪水：打掃（次數×2）＋午餐工作（次數×2）＋班級常規獎勵（達成天數×1＋全勤3，上限 8）各建一筆（2026-08-14 起，取代算利息）。
4. 回報：全班收支摘要（職務薪／打掃／午餐／常規獎勵分開列、總獎懲、餘額前後三名以座號列出）。

平時零星記帳（消費、臨時獎勵）隨時一句話即可。

## 七、前台「🏦 小小銀行」頁

- **存摺查詢（加密）**：學生輸入座號＋查詢碼（沿用學習報告同一組查詢碼），
  看餘額與最近交易明細（存摺樣式）。加密機制與學習報告相同（PBKDF2＋AES-GCM）。
- **商店櫥窗（公開）**：品項、價格、庫存狀態，無任何個資。
- **金融小知識輪播（公開）**：儲蓄、利息、需要 vs 想要等中年級理財觀念。

### 兌換申請流（能看也能買，2026-07-18 上線）

靜態班網無法直接扣款，採「**學生申請 → 老師核可**」兩段式（符合師控理念）：

1. **學生端（bank.html）**：打開存摺後，商店卡片出現「🛒 我要兌換」——
   只有「餘額夠＋有庫存」才能按；不足顯示「還差 N 幣」（存錢目標感）。
   按下→確認→送 Apps Script 代理 `redeem_request`。
2. **代理端驗證**（不信任前端）：以座號＋查詢碼對名冊驗證身分；品項與價格一律
   以 Notion 商店為準；每人同時最多 **3 筆待處理**申請（防洗版）。
   通過→寫入 Notion「**🛒 兌換申請**」（狀態=待處理，**不扣款**）。
3. **教師端（teacher.html 教師專區「🛒 兌換申請」區塊）**：
   - **✅ 核可**：代理自動──帳本建「消費」列扣幣（餘額不足會先警示，可強制）
     → 商店庫存 −1 → 申請設「已完成」＋處理紀錄（扣多少、餘額多少）。
   - **❌ 駁回**：填原因，狀態設「已駁回」（不扣款）。
   - 處理完按「立即更新班網」，學生存摺與商店庫存才會更新到站上。
4. **購買明細**：「🛒 兌換申請」DB 即明細正本（誰、買什麼、多少幣、何時申請
   ／處理、狀態、備註），教師專區可看最近 50 筆，完整搜尋進 Notion。

資料庫「🛒 兌換申請」欄位：申請(title)、座號(number)、品項(text)、價格(number)、
狀態(select：待處理/已完成/已駁回)、處理時間(date)、備註(text)、
商店頁ID(text，核可扣庫存用)、申請時間(created_time)。
